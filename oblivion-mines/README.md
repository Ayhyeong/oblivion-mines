# 망각의 지뢰 (Oblivion Mines)

11×11 보드 위에서 두 사람이 서로의 지뢰 배치를 모르는 채 이동하며 점수를 겨루는 비대칭 정보 보드게임.
**온라인 1:1 전용**이며, 서버 없이 두 브라우저가 WebRTC 로 직접 연결된다.
GitHub Pages 같은 정적 호스팅에 올리면 그대로 돌아간다.

> 배포: 저장소 Settings → Pages 를 **GitHub Actions** 로 지정하면
> `https://<사용자>.github.io/<저장소>/` 에서 열린다.

---

## 어떻게 연결되나

**서로 다른 인터넷 회선이어도 된다.** 집 Wi‑Fi와 회사 Wi‑Fi, 서울과 부산, 유선과 모바일
데이터 — 상관없다. 공개 STUN 서버로 NAT를 뚫는 것이 정확히 이 용도다.
같은 네트워크에 있을 필요가 없다.

중계 서버가 없으므로 **대국을 시작할 때 딱 한 번만** 사람이 코드를 전달한다.

1. 한쪽이 **방 만들기** → 초대 링크(또는 초대 코드)가 나온다.
2. 상대에게 링크를 보낸다. 링크를 열면 방 설정이 보이고, 참가하면 **응답 코드**가 나온다.
3. 그 응답 코드를 방을 연 사람에게 보내 붙여넣으면 연결된다.

**여기까지가 수동 단계의 전부다.** 연결된 뒤로는 배치 → 대국 → 리빌·검증까지 전부 자동으로
오간다. 수를 둘 때마다 무언가를 보낼 필요는 없다.

### 드물게 연결이 안 되는 경우

일반적인 가정용 공유기는 해당되지 않는다. 문제가 되는 것은 **대칭형 NAT** 뿐이고,
일부 회사망과 이동통신사 망에서 쓰인다. TURN 중계 서버를 두지 않았기 때문에 이 경우에는
경로를 찾지 못한다.

대칭형 NAT는 한쪽만 벗어나도 대개 뚫리므로, 둘 중 한 사람이 다른 회선으로 바꿔
(예: 회사 Wi‑Fi → 모바일 데이터) 방을 새로 열면 된다.

## 서버 없이 어떻게 판정하나

이 게임의 어려운 점은 **양측이 서로 다른 정보를 본다**는 것이다. 권위 서버가 없는데도
상대 지뢰를 숨기려면, 판정을 "각자 자기 몫만 계산해서 합치는" 구조로 바꿔야 한다.

매 수 오가는 것은 **숫자 두 개뿐**이다.

| 값 | 뜻 | 언제 보내나 |
|---|---|---|
| `mine` | 목적지 칸에 내 지뢰가 있는가 (0/1) | 목적지가 미방문·비보물 칸일 때 |
| `adj` | 목적지 칸에 인접한 내 지뢰 개수 (0~8) | 판정이 **'신규 칸'으로 확정된 뒤에만** |

- 방문한 칸에는 살아 있는 지뢰가 존재할 수 없고(밟는 순간 터진다) 보물 칸은 배치 금지이므로,
  그런 칸으로 갈 때는 교환 자체가 없다.
- 폭발·보물·기방문 칸에서는 규칙이 인접 정보를 주지 않으므로 `adj` 를 **전송하지 않는다.**
  자기 지뢰를 밟은 쪽이 그 칸 주변 정보를 덤으로 얻는 일이 없다.
- '신규 칸'일 때 두 `adj` 의 합은 어차피 공개되는 판정 결과(+N)이고 각자 자기 몫을 알고 있으므로,
  주고받아도 규칙이 주지 않는 정보가 새지 않는다.

그래서 **상대 지뢰 집합은 내 브라우저 어디에도 존재하지 않는다.** 판정 함수도 상대 지뢰를
건드리지 않는다 — `resolveMove(state, side, to, facts)` 는 합산된 숫자만 받는다.

### 정보 위생 — 보증의 정확한 범위

보증은 **"사람이 실제로 얻는 정보 = 규칙이 주는 정보"** 다. 세 가지로 나뉜다.

1. **화면에는 언제나 총합 하나만 나온다.** `+3` 이라고만 뜨고 `내 2 + 상대 1` 로 쪼개 보여주는
   곳은 어디에도 없다. 배치가 끝난 뒤에는 내 지뢰의 위치도 개수도 표시하지 않는다.
   자기 지뢰를 잊는 것이 이 게임의 전제이므로, 잊은 것을 되살려 주는 표시는 전부 뺐다.
2. **규칙이 총합조차 주지 않는 국면에서는 전송도 하지 않는다.** 폭발·보물·기방문 칸에서
   `adj` 를 보내지 않는 것이 그것이다(위 표 참고).
3. **프로토콜이 지우지 못하는 것 하나.** 양측이 각자 자기 지뢰 비트를 보내므로, 폭발한 칸의
   지뢰가 1개였는지 2개였는지는 서로 알게 된다.

3번은 구현의 빈틈이 아니라 산술이다. 내가 내 몫 `a` 를 알고 총합 `a+b` 를 알면
`b = (a+b) − a` 다. 총합만 알게 하려면 내가 내 몫을 몰라야 하는데, 클라이언트는 내 지뢰로
`a` 를 계산해야 하므로 반드시 안다. 가산 동형암호나 임계 복호화를 써도 같다 — 복호화에
참여하는 쪽은 자기 입력을 알고 있다. 신뢰할 제3자(서버)나 본격적인 MPC/ZK 없이는 막을 수
없으며, 이는 기획안 §7.2의 결론("완전 무신뢰 구현은 ZK 증명이 필요하다 — MVP 범위 밖")과
같다. 이미 터져 사라진 칸에 대한 정보이고, 대국 중 화면에는 표시하지 않는다.

### 상대가 거짓말을 하면

할 수 있다. 그리고 **끝나면 반드시 드러난다.**

대국 전에 양측은 배치를 해시로 봉인한다(§7.2 커밋‑리빌).

```
salt   = 32 랜덤 바이트
digest = SHA-256( salt ‖ cells.sort().join(',') )
```

종료 시 양측이 `{cells, salt}` 를 공개하면 화면이 두 가지를 즉시 검증한다.

1. **해시 검증** — 공개한 배치가 대국 전 커밋과 맞는가. 도중에 지뢰를 옮기는 조작을 막는다.
2. **리플레이 재현** — 전체 기보를 규칙 코어로 처음부터 재실행해, 매 수의 점수와 최종 점수가
   기록과 일치하는가. 상대가 `mine` 이나 `adj` 를 한 번이라도 속였다면 여기서 어긋난다.

매 수마다 공개 상태의 지문(FNV‑1a 해시)도 함께 보내 두 판이 갈라지면 즉시 중단한다.
지문에는 지뢰가 들어가지 않으므로 이 값 자체로는 아무것도 새지 않는다.

`기보 내보내기` 로 받은 JSON 은 시작 화면의 **기보 검증** 에서 제3자가 다시 검증할 수 있다.

| 구성 | 위치 | 설명 |
|---|---|---|
| 규칙 코어 | `src/rules/` | 의존성 없는 순수 TypeScript. 판정·검증·리플레이가 같은 코드를 쓴다. |
| 네트워크 | `src/net/` | WebRTC 래퍼, zod 스키마 프로토콜, 시그널링 코드 인코딩, 대국 세션 |
| 웹 UI | `src/ui/` | 프레임워크 없는 DOM 구현 |
| 테스트 | `tests/rules.test.ts` | §2.7 엣지 케이스 표(E1–E10) + 무작위 200판 + **P2P 교환 100판** |
| 배포 | `.github/workflows/deploy.yml` | push → 타입체크 → 테스트 → 빌드 → Pages |

핵심 테스트 하나: 무작위 대국 100판을 "전지적 판 1개 + 자기 지뢰만 아는 피어 2개"로 동시에
돌리면서, 매 수 세 상태의 공개 지문이 모두 일치하는지 확인한다. 피어의 상대 지뢰 집합이
끝까지 비어 있다는 것도 함께 검사한다.

## 규칙 요약

- **보드** 11×11. 열 `a`~`k`, 행 `1`~`11`. 인접은 8방향.
- **금지 칸 11개** 白 `a1 a2 b1 b2`, 黑 `k11 k10 j11 j10`, 보물 `a11 f6 k1`. 배치 가능 110칸.
  세 보물은 `col + row = 10` 안티대각선 위에 있다.
- **배치** 각자 15칸. 양측이 같은 칸을 골라 한 칸에 지뢰 2개가 놓이는 것은 허용된다.
- **이동** 白 선공, 인접 8칸 중 하나로. 상대 말이 있는 칸은 불가.
- **점수** (우선순위 순)
  1. 지뢰 → `-5`. 그 칸의 지뢰는 양측 것 모두 소멸, 시작 구역으로 복귀.
  2. 미획득 보물 → `+10 / +15 / +20`. **인접 지뢰는 세지 않는다.**
  3. 이미 밟은 칸(양측 통합) → `0`.
  4. 신규 칸 → 인접 8칸의 지뢰 총 개수(양측 합산, 한 칸 2개면 2).
- **종료** 보물 3개 회수 시 즉시, 또는 각자 60수 도달 시 점수 우위로, 또는 기권.

자기 지뢰도 밟으면 `-5`이고 자기 지뢰도 인접 점수에 포함된다. 그리고 대국이 시작되면
**자기 지뢰조차 표시되지 않는다.** 이 세 가지가 게임의 축이다.

### 룰셋 파라미터

방을 여는 쪽이 정하고, 초대 코드에 실려 상대에게 전달된다. 참가하는 쪽은 수락 전에 전부 확인할 수 있다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| `mineCount` | 15 | 한 명이 까는 지뢰 수 |
| `treasureAwards` | `[10, 15, 20]` | 보물 회수 순서별 점수 |
| `minePenalty` | −5 | 지뢰 페널티 |
| `plyLimit` | 60 | 각자 최대 수 |
| `komi` | 0 | 후공(黑) 보정 — §10.1 선공 이점 대응 |
| `countOwnMines` | true | 끄면 인접 점수에서 자기 지뢰 제외(추론 모드) |
| `showOwnMines` | **false** | 켜면 내 지뢰만 표시 — **망각 모드의 전제가 깨진다** |

## 조작

| 동작 | 입력 |
|---|---|
| 이동 / 지뢰 놓기 | 클릭 · 탭 |
| 지뢰 의심 표시(플래그) | 우클릭 · 길게 누르기 · `F` |
| 커서 이동 | 방향키 |
| 확정 | `Enter` · `Space` |
| 선택 취소 | `Esc` |

모바일에서는 칸이 약 27px 가 되므로 **탭 → 확인** 2단계 입력이 기본으로 켜진다(§9.4).

추론 보조는 **수동 플래그 하나뿐**이다(§9.3). 자동 추론·제약 충족 계산은 넣지 않았고,
플래그는 상대에게 전송되지 않으며 내 기기에만 남는다.

## 범위

포함: 온라인 1:1 · 커밋‑리빌 · 리플레이 재현 검증 · 매 수 상태 지문 대조 · 기보 내보내기/검증 ·
룰셋 협의 · 재연결 따라잡기 · 키보드 조작 · 모바일 레이아웃.

미포함:

- **AI 상대·자동 플레이·자동 추론 보조** — 넣지 않았다(기획안 §1.3, §9.3).
  배치 프리셋, 진출로 경고, 배치 타임아웃 자동 제출도 같은 이유로 제거했다. 배치는 전부 수동이다.
- **한 기기 교대 대전** — 제거했다. 온라인 1:1 만 있다.
- **권위 서버**(§8 WebSocket, §7.1 L2 서버 조작 방어, §7.4 사이드 채널 패딩, L5 다중 계정 탐지)
  — 서버가 있어야 성립하는 항목이라 P2P 구조에서는 제외했다. 대신 커밋‑리빌과 리플레이 검증이
  사후 검출을 담당한다.
- **TURN 중계** — 위의 연결 실패 사유 참고.

## 기획안과 다르게 정한 것

- **`showOwnMines` 기본값을 `false`** 로 두었다. §10.4 주석은 기본 `true` 라고 적혀 있지만
  §4.2·§10.3 과 제목이 모두 반대를 가리킨다. §4.2 를 규범으로 보고 망각 모드를 기본으로 잡았다.
- **수 상한 판정 시점** — "각자 60수"를 양측 모두 60수를 둔 직후 종료로 구현했다.
  白 선공이므로 이렇게 해야 양측이 같은 수를 둔다.
- **폭발 시 지뢰 개수** — §정보 위생 참고. 대국 중에는 표시하지 않고, 종료 후 리빌 화면에서만
  `×2` 로 보인다.
